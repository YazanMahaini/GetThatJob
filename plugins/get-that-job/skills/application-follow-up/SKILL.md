# ApplicationFollowUp

Use when the applicant asks for the status of a tracked application, to review a recruiter message, or to follow up after a confirmed submission. If `.getthatjob/setup.json` is absent, use [SetupSkill](../setup-skill/SKILL.md) first while preserving existing records. Read `AGENTS.md`, `OPERATIONS.md`, the matching tracker row, and packet before checking the specified employer portal or the email plugin selected for this workspace. Use that plugin's read-only tools for mailbox checks; do not switch plugins or ask for a plugin `@` mention on a resumed workspace.

Match the exact employer, role, requisition, and applicant account. Capture the employer's wording, observation time and zone, evidence link or short quote, deadline or interview date, and next action. Keep the internal tracker stage separate from the employer's status. A portal's last-updated date may change after viewing or editing; it is not by itself a submission date or proof of a new application. Preserve the original submission and receipt history when adding later updates.

Do not reply to recruiters, schedule or decline interviews, withdraw applications, accept offers, or change portal answers without the user's applicable instruction. If a response is requested, prepare a draft or carry out the explicitly authorized action. Report the current verified stage, any discrepancy across sources, and the next deadline. Run checks when requested; create a recurring monitor only when the user asks for one.
