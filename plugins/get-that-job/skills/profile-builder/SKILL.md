# ProfileBuilder

Invoke after **each filled and checked application draft**, including a material update to a saved draft, whether JobFinder or the applicant filled it. Invoke after submission if verified reusable answers from that application have not yet been captured. If setup has not run in this workspace, use [SetupSkill](../setup-skill/SKILL.md) first. Read the approved CV index, `MEMORY.md`, the existing `APPLICATION_PROFILE.md`, the just-filled application packet, and the verified portal answers. On first use in an existing workspace, also check already verified facts in `MEMORY.md` and completed application packets for reusable answers. The applicant's active instruction takes precedence if they do not want a particular fact retained.

Identify answers that will help with future forms and are not already clear in the approved CV: for example date or place of birth, nationality, residence, contact preferences, language proficiency, availability, or a user-confirmed form convention. **Merge** each newly verified fact into `APPLICATION_PROFILE.md`; keep existing unrelated entries, corrections, and source history. Match an existing entry by field and reuse scope, update it only when the new evidence supports a change, and avoid duplicate rows for the same answer. Record each fact's exact value, original source, confirmation date, and reuse scope. If this application yields no new or corrected reusable facts, leave the profile intact. A value entered into a portal is not proof by itself; trace it to a direct user statement, official document, or other approved source. Note in the packet which facts were promoted to the reusable profile. Do not treat a receipt email alone as proof of a form answer.

Use the general-facts table only for stable applicant facts. Put work-authorization answers, application-specific eligibility, salary expectations, referee-contact permission, disclosures, consents, and portal date conventions in the scoped table with the exact question or context and a recheck rule. Never reuse a country-specific or employer-specific answer as a universal answer. Do not save passwords, one-time codes, payment details, or irrelevant private document contents. Preserve corrections and flag conflicts; do not silently replace an older fact with a stronger claim.

Before asking a question in the next application, read `APPLICATION_PROFILE.md` and reuse a still-valid answer whose scope covers the new field. Ask again only if the value is missing, conflicting, stale, requires a new commitment, or the new question changes its meaning. Keep this file inside the applicant workspace and never upload it as an application attachment.
