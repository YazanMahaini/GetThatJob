# ApplicationFinalize

If `.getthatjob/setup.json` is absent in the selected workspace, use [SetupSkill](../setup-skill/SKILL.md) first, preserving any existing application records.

Use when the user explicitly directs final submission of a specific prepared application, or when a complete checked draft is handed off under `automatic-submit` in `OPERATIONS.md`. A missing mode means `stop-and-wait`. Read workspace `AGENTS.md`, `OPERATIONS.md`, and `APPLICATION_PROFILE.md`, its tracker row and packet, the live posting, and the current portal draft. Verify the employer and destination, requisition, eligibility, deadline, fees, duplicate status, answers, and final document versions. Ask only about an unresolved required fact or commitment that cannot be sourced.

Before touching final Apply/Submit, independently verify opportunity choice: the applicant directly instructed submission of this specific employer and role, previously selected this specific posting for application, or explicitly saved a standing automatic opportunity scope in `OPERATIONS.md` that covers this posting. Check that the scope still matches its role, location, compensation, exclusions, and live requirements; search preferences in `TARGET_ROLES.md` or a generic search request are not submission authorization. Record the choice or exact scope match and source/date in the packet and tracker notes. If none exists, present the opportunity for the applicant's selection and stop before submission, even when the saved mode is `automatic-submit`. The specific instruction or a saved `automatic-submit` mode **together with** a matching opportunity choice authorizes the final Apply/Submit control for a fully checked, eligible application without another approval. Neither authorizes entering the user's name in an e-signature or certification-signature field, checking a signature-equivalent affirmation, or signing a binding declaration. Obtain explicit instruction to sign that particular application when such a field blocks submission. Preserve the standing mode unless the applicant explicitly changes it; a one-off submission instruction changes only that application. Do not pay fees or accept employment terms as part of routine submission.

After a permitted final action, inspect the confirmation page or application history. Record the observed timestamp, exact employer status, and evidence in the packet and `APPLICATIONS.csv`; mark `submitted` only when the evidence establishes it. If the result is unclear, record an unresolved attempt rather than claiming success. If final corrections introduced newly verified reusable answers, invoke [ProfileBuilder](../profile-builder/SKILL.md). Then use [EmailConfirmationChecker](../email-confirmation-checker/SKILL.md) to check the selected email plugin and record a matching receipt or the precise access limitation.
